# tokenfund seeding plan: one dense cluster first (2026-11-06)

Alex: "network theory with dense network ... start with that, build trust from there, smaller or more open communities should start that".

## Idea
Don't spread thin. Network effects only start once one small group sees each other give and build (atomic network:
~20-50 people who all know the same 1-3 projects). Then copy that cluster next door.

## Cluster 1 = Claude Code users with spare weekly usage
- Hook: "Your weekly Claude Code limit resets soon. The unused part is gone. Give it to an open source project instead."
  Real, recurring pain every week, measurable, and exactly what the product does.
- Place: the builders' Discord https://discord.gg/spUZ8ruSDJ (#fund-builders in MyClawn Community) + the open dev communities our Labs phone already has accounts on:
  dev.to, Hashnode, Bluesky, Mastodon, X, Indie Hackers, Labs Discord. No unsolicited GitHub issues (GitHub spam rule).
- Focus: ONE shared-vision project at a time (start: Hide & Clone, the most-built one, 45M tokens), so every backer sees the
  others' PRs merged on the live board. Leaderboard + "first backer" badge = status for early people.
- Proof posts: real merged PRs from backers, live board screenshots, the token counter moving. No fake numbers.

## Cluster 2+ (after cluster 1 has ~10 backers with merged PRs)
- Small open source maintainers who already welcome AI PRs (AGENTS.md / CLAUDE.md in repo, "good first issue"): invite them
  via their own Discord/Discussions where self-promo is allowed, or a PR to awesome-claude-code style lists.

## Measure (feedback loop)
- tokenfund visits by utm_source, + presses, sessions started, receipts (tokens), merged PRs, new listings per week.
- Double down on the channel with most + presses per post; drop the wording that gets none after 3 posts.
